# M7a 容器内条目预览

状态：**M7a 已实现并通过 Finder 实机验收**。M7b（归档内表格与结构化类型的补齐、窗格缓存与性能调优）尚未开始。

## 本阶段范围

在文件夹、ZIP 与其他归档的树形列表中点击某个文件条目时，在窗口**右侧**的就地预览窗格中显示该条目的内容。左树与右窗格由可拖拽的 `NSSplitView` 分隔。**窗格默认收起**，只在选中可预览的文件时自动展开；选中文件夹/链接或取消选中时重新收起，因此未选中文件时左树占满窗口宽度。容器类型（文件夹/归档/结构化）显示分栏，其余类型保持原有的单视图布局。

两类来源的能力不同，因为既有解析器大多以文件 URL 为输入：

- **文件夹来源**：子项是真实文件，直接复用 `PreviewLoader`，因此嵌套 ZIP、SQLite、JSON、CSV、列式数据等全部可用。
- **归档来源**：条目在内存中抽取，**不写磁盘**，因此只能覆盖可从 `Data` 解析的类型。

## 已实现

- `EmbeddedPreviewLoader`：目录子项与归档条目两类来源。目录子项拒绝路径越界（`..` 与超出容器前缀）、符号链接、目录与非普通文件；归档条目有单条目 16 MiB 上限、5 秒扫描超时，加密条目与需要文件路径的类型**明确拒绝**而非静默降级。
- `ImagePreview`：ImageIO 缩略图解码。文件 >64 MiB、最长边 >10000 px、>2000 万像素的图片在分配任何像素缓冲前即被拒绝（解压炸弹防护），缩略图上限 2048 px 并重编码为 PNG。
- `PreviewSnapshot` 扩展：新增 `.image` 类型、`imagePNGData`（PNG 字节，保持 `Sendable`，不让 `CGImage` 跨并发边界）、`Item.sourcePath`（**未转义**的容器内定位路径）。
- 既有解析器新增内存入口：`DocumentPreview`、`DiagramPreview`、`PropertyListPreview`、`CommonTextPreview`。
- 扩展 UI：`NSSplitView` + `DetailPreviewPane`，可显示图片、文本、代码、Markdown、表格、结构树、图表与嵌套容器条目列表；选中变化沿用 `generation` 竞态防护模式。窗格默认收起，选中可预览文件时以 0.18 秒动画展开；收起时同时依赖隐藏子视图与把分隔条推到边缘两种机制，避免只靠其中一种。
- `SpaceLens.xcodeproj/project.pbxproj` 注册两个新 Core 文件（该工程为逐文件显式引用）。

## 修复记录

**首次实机验收时右窗格只显示标题与摘要，内容区为空白。** 当时的判断是 documentView 尺寸为零，修法是显示前把 documentView 对齐可视区域、在 `layout()` 中同步宽度、图片按窗格宽度等比缩小。这一层修改是必要的，但**不是根因**。

**真正根因（经几何诊断日志确认）**：窗格标题栏（标题 / 副标题 / 分隔线）只有 top 约束、**没有高度约束**，竖直方向的剩余空间被 Auto Layout 分配给了它们，把内容滚动区压缩到几乎为零。日志实测：

| | 修复前 | 修复后 |
|---|---|---|
| 文本滚动区 | 355 × **30**，随后变成 355 × **2** | 355 × **415** |
| clip 视图 | 336 × 28，随后 336 × 0 | 353 × 413 |
| 文本视图 frame | 336 × 1（与 clip 不一致） | 353 × 413（与 clip 一致） |
| 文本容器宽度 | 316 | 333（= 353 − 内边距） |

修复：给标题栏三个视图设置 `.required` 的竖直 hugging / compression resistance、给分隔线固定 1 点高度、把内容滚动区的竖直 hugging 设为低优先级（由它吸收剩余空间）。主视图的分隔线存在同类隐患（同样没有高度约束，只是恰好未触发），一并加上固定高度。

**过程教训**：这个 bug 连续误判了两轮，因为我依据症状（文字被挤到一边、出现横向滚动条）去猜"文本容器宽度不对"，而真正错的是外层布局。第三轮改为**在关键位置打印真实几何数值**后一次定位。附带发现 `strings` 默认不扫描 Swift 字面量所在的段，需要用 `grep -a` 才能确认二进制里是否含某段代码——否则会误判"安装未生效"。

**同时暴露一个流程缺陷**：`release-check.sh` 构建到自己的临时目录，**不会**刷新 `install.sh` 读取的默认 derived data，导致一次验收实际装的是旧构建（日志中完全没有诊断输出，才得以发现）。已在 `install.sh` 增加"构建产物早于 `Sources`/`Config` 源文件"的告警。

## 验收后的稳定性与界面完善

本轮在 M7a 实机使用基础上完成并验收：

- 图片尺寸先逐边检查再计算总像素数，避免恶意元数据触发整数乘法溢出。
- 目录条目读取逐级拒绝符号链接，并在解析后再次校验路径仍位于授权根目录内，覆盖中间路径软链接逃逸场景。
- 右侧条目切换会取消实际后台任务，并继续使用 generation 标识阻止过期结果覆盖当前内容。
- 所有主预览与右侧详情滚动视图使用常驻、独立占位的滚动条区域；轨道和右下交汇角为不透明背景，内容不会显示在滚动条下方。
- 左右窗格之间不绘制分割线，但仍可拖动调整宽度；左右内容区底边对齐。
- 右侧标题栏加入圆角矩形“关闭”按钮，点击后取消当前加载与选择并收起右侧预览。
- 日期继续使用系统区域设置；文件关联保持 Quick Look 预览角色，不接管双击打开。

验证结果：56 项核心测试、Release 通用二进制、签名、Quick Look 扩展与 preview-only 文件关联检查全部通过；Finder 实机验收通过。阶段样例 `build/fixtures/m7-scrollbars` 已在验收后删除。

## 已知限制

- 归档内需要文件路径的类型（SQLite、Parquet/Arrow/Feather/Avro）与嵌套容器：明确提示不支持，避免为了预览而写入磁盘。文件夹内的同类文件不受此限。
- 归档条目单次读取上限 16 MiB，超出时提示“仅显示前 …”；TAR 系列为顺序扫描，超时上限 5 秒。
- 容器内的 PDF 不预览（顶层仍由 macOS 原生预览处理）。
- 嵌套容器只列出条目，不能继续深入。
- 暂未实现：窗格内的条目导出/另存为（与“不落盘”约定冲突）、图片元信息展示。
